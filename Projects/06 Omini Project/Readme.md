### The Process Behind Building a Website

### 1. Define

Website ကို ဘယ်သူ့အတွက် ဘာအတွက် တည်ဆောက်မာလဲ? သတင်းအတွက်လား product ရောင်းမို့အတွက်လား စာသင်မို့အတွက်လား စသည်ဖြင့်၊ target audience ကို သေချာစဉ်းစားရပါမယ်။ target audience ကို အဓိကထားပီးတည်ဆောက်ရင် website ကို ဘယ်သူအတွက် တည်ဆောက်ထားလဲဆိုတာ သိလေလေ project အောင်မြင်မှုများလေလေ ဖိပါတယ်။ ဒါကြောင့် ဒီအဆင့်ကို ကျော်ပီး website တည်ဆောက်ခြင်းမလုပ်ပါနဲ့။ ဒီအဆင့်တစ်ခုတည်းတောင် Competition Research, User Prsonas တို့လို အကြောင်းအရာတွေ စသည်ဖြင့် အသေးစိတ် သွားမို့ လိုပါတယ်။

### 2. Plan the Project

ဒီအဆင့်မှာ သတ်မှတ်ထားတဲ့ Business Goal, User Goal and Target Audience တို့အပေါ် အခြေခံရပါမယ်။ websit content ကို plan ချပီး စုဆောင်းရပါမယ်။ ပုံမှန်အားဖြင့် content တွေကို client က ပေးသင့်ပါတယ်။ ဒါပေမဲ့ ကိုယ့်ဘက်ကလည်း content တွေ ထုတ်ပေးနိုင်ပါတယ်။ big company တွေကတော့ သူတို့ဘက်က content တွေ ပေးတတ်ပါတယ်။ Small company တွေကတော့ content တွေ အဆင်သင့်ရှိမနေပါဘူး။ ဒါဆိုရင် copywriter ငှားပြီး content တွေ ဖန်တီးပေးရပါမယ်။ ဒီအတွက် extra charge သက်သက်တောင်းရပါမယ်။ Image ရှာပေးတာလောက်တော့ အဆင်ပြေပါတယ်။ Site က ကြီးတယ်ဆို‌ရင်တော့ sitemap အတွက်လည်း plan ချမို့လိုပါတယ်။ Site မှာ ဘယ် page တွေလိုမလဲ content တွေနဲ့ page တွေ ချိတ်ဆက်ပီး အလုပ်လုပ်မလဲ စသည်ဖြင့်။ content ကို အရင်စဉ်းစားပီမှ page ကို တည်ဆောက်ပါ web design ကို အရင် တည်ဆောက်ပီမှ content ထည့်ခြင်းမပြုလုပ်ပါနဲ့။ ပီးတဲ့အခါမှာ web personality ကို သေချာစဉ်းစားပြီးရွေးချယ်ပါ။

### 3. Sketch layout and Component Ideas

Content နဲ့ Message ကို နေရာချမို့ Layout ကို စတင်စဉ်းစားရပါမယ်။ ဒီနေရာမှာလည်း content ကပဲ Design ကိုဦးဆောင်ရပါမယ်။ component တွေနဲ့ layout ကို အကြမ်းဖျင်း သိရပီဆိုရင်တော့ paper or figma, adobe xd တို့နဲ့ design ဆွဲသင့်ပါတယ်။ Detail ဖိစရာမလိုပါဘူး။ (like wireframe) text တွေ တကယ်ရေးစရာမလိုဘူး image တွေနေရာမှာ box တွေ ဆွဲလို့ရပါတယ်။ layout idea တွေကို sketch ဆွဲတဲ့ process က အလွန်အရေးကြီးပါတယ်။

1. Iterative Process - ဘာကိုမှ အပီးသတ် သတ်မှတ်ထားစရာမလိုသေးဘူး။ idea ကို အကြမ်းပုံဖော်ရုံသက်သက်အတွက်သာ code ကို implement လုပ်တဲ့အခါမှာ ပြန်ချိန်းလို့ရပါတယ်။

2. Layout Design မရှိဘဲ code ကို implement လုပ်မို့ မစဉ်းစားပါနဲ့

### Responsive Design Ingredients

1. Fluid Layouts

- To alllow webpage to adapt to the `current viewport` width(or even height)
- Use %(or vh/vw) unit instead of px for el that `should adapt to viewport(usually layout)`
- Use max-width instead of width

2. Responsive Units

- Use `rem` unit instead of px for most length
- To make it easy to `scale the entire layout down` (or up) automatically
- `Helpful trick` setting 1rem to 10px for easy calculations

3. Flexiable Images

- By default, images `don't scale automatically` as we change the viewport, so we need to fix that
- Alays use % for image dimensions, together with the max-width property

4. Media Queries

- Bring responsive sites to life!
- To change CSS style on `certain viewport widths`(called breakpoints)

### Desktop-First Vs Mobile-First Development

### Desktop-First

- Start writing CSS for the desktop: `Large screen`
- Then, media queries `Shrink design` to smaller screens.

> screen အကြီးအတွက် အရင်ရေးတယ်။ ပီးမှ media queries ကိုသုံးပီး `mobile size` ပြန်ရေးတယ်။ အသုံးပြုရ ပိုလွယ်တယ်။

### Mobile-First

- Start writing CSS for mobile devices: `small screen`
- Then, media queries `expand design` to a large screen
- Forces us to reduce websites and apps to the `absolute essentials`.

> screen အငယ်အတွက် အရင်ရေးတယ်။ ပီးမှ media queries ကိုသုံးပီး `Desktop size` ပြန်ရေးတယ်

### REM and max-width

```css
html {
  /* font-size: 10px; */

  /* 10px လို့ သတ်မှတ်တာက ကောင်းပေမဲ့ User က browser ကနေ font size ကို ကြီးစေလိုတဲ့အခါ အလုပ်ဖိမှာမဟုတ်ဘူး ဒါကြောင့် px အစား percentage ကို သုံးသင့်ပါတယ်။ */

  /* Percentage of User's browser font-size setting */
  font-size: 62.5%; /* 10/16 = 0.625 = 62.5% */
}

.test {
  background-color: tomato;
  /* width: 1000px;  */
  /* max-width: 1000px;  */

  max-width: 50rem;
  padding: 4rem;
  font-size: 2rem;
  color: #fff;

  /* 
  Default Browser —
  1rem = 16px --> 50rem = 800px 
  
  if html selector set font-size to 10px —
  1rem = 10rpx --> 50rem = 500px */
}
```
